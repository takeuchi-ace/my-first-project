## D. 一括修正の方針（提案）

### 1. 修正規模の評価

### 2. 修正アプローチ比較

| アプローチ | 対象 | 工数 | リスク |
|-----------|------|------|--------|
| A: prompt 修正 | caddy_tip, drunk_praise | 2件 | 低 |
| B: choices 修正 | opponent_ball_mark, caddy_ball_advice | 2件（delta/tags も調整必要） | 中 |
| C: speech 修正 | curatedEvents 7件 | 7件 × 1-2行 | 低 |

### 3. 推奨修正順序

**Phase 1（即時修正可能、影響小）**:
1. `caddy_tip` の prompt 修正（1行変更）
2. `drunk_praise` の prompt 修正（1行変更）

**Phase 2（choices 再設計が必要）**:

5. `caddy_ball_advice` の choices 再設計（3択の差別化）

### 4. テンプレ化について

**「prompt をテンプレ化して揃える」 vs 「choices をテンプレ化して揃える」**:

→ **どちらも不要**。

現状の prompt は以下の一貫したパターンを既に満たしている：
```
[状況の説明]。[相手の反応/感情]。
```

choices も以下のパターンを概ね満たしている：
```
A: 安全/中立な対応 (safe/etiquette)
B: 積極的/大胆な対応 (bold/humor)
C: 極端/リスキーな対応 (extreme/cheat)
```

問題はテンプレの欠如ではなく、**個別イベントの微修正**で解決可能。
一括テンプレ化は既存の多様性を損ない、ゲーム体験を単調にするリスクがある。

### 5. 作業単位

修正は以下の3カテゴリに分けて実施：

1. **prompt 修正**（2件）: events.ts の description フィールドを書き換え
2. **choices 修正**（2件）: events.ts の choices 配列を再設計（delta/tags 含む）
3. **speech 修正**（7件）: curatedEvents.ts の speech オブジェクトを書き換え

合計: **11件のイベント、約20行の変更**で全NG解消可能。
