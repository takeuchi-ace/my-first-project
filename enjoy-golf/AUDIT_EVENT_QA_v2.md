# イベントテキスト再監査レポート（第2版）

**作成日**: 2026-07-25
**対象**: enjoy-golf 全イベントデータ（現行）
**ステータス**: レポートのみ（コード変更なし）
**前版**: `AUDIT_EVENT_QA.md`（2026-02-22）

## 監査方法

1. イベントデータ全ファイルを精読（events / curated / character / lunch / female / extreme / goodBack / tensionBack / ace / competition / morningShot / putting）
2. データを実際に require し、本番と同じ経路（`applyChoice` → trait補正 → キャラreactions → likes/hates → クランプ → `evaluateReactionRank`）で全1,160選択肢 × 21キャラをシミュレーション
3. 到達可否・重複・tag被覆・選択肢位置の偏りを機械集計

**未実施**: 実機プレイによる目視確認。表示崩れ・演出タイミングは本レポートの対象外。

## E. ロジック不整合 — 優先度: 中

### E-1. 最終パットの「誤ったアドバイス」が機能しない

`puttingEvent.ts` は `adviceAccuracy` で正誤を振り分けるが、誤アドバイス時の文言が傾斜によって分岐していない:

- `ONIZUKA_PROFILE`: 誤アドバイスは常に「右に外してみては！勢いで決めろ！！」
- `GENERIC_PROFILE`（19キャラ）: 誤アドバイスは常に「右に外してみてはどうでしょう」

ところが slope `left` の `correctAim` は `right`。**傾斜が左のとき、誤アドバイスがそのまま正解になる**。鬼塚と汎用19キャラ、つまり20/21キャラで読み合いが成立しない。`TANAKA_PROFILE` は傾斜ごとに分岐しており問題なし。

### E-2. creep が二つの意味で使われている

本来「気持ち悪さ／距離感の失敗」を表すゲージだが、「場を冷やした」ペナルティとしても流用されている:

- 「…」と黙る → creep +9（`char_13_2`）
- 無言で目をそらす → creep +9（`char_10_5`）
- 「時間大丈夫ですか？」 → creep +8（`char_3_1`）
- 「科学的根拠はあるんですか？」 → creep +10（`char_6_5`）

プレイヤーには「なぜ黙ったら気持ち悪がられるのか」が伝わらない。ゲージ名と体験の乖離。

### E-3. worst の発生率が高い

| ファイル | worst率 |
|---|---|
| lunchEvents | 48.2% |
| tensionBackEvents | 47.8% |
| femaleEvents | 42.4% |
| characterEvents | 41.4% |
| events.ts | 23.6% |

キャラ固有・ランチという「そのキャラらしさが出る場面」ほど、選択肢の4割が最悪反応になる。

### E-4. 宣言済みtag 43種のうち4種が未使用

`self_suppress` `over_adjust` `over_flatter` `forced_laugh`（キャラ側の `reactions`/`likesTags`/`hatesTags` からも参照されていないため、実害はないが定義だけ残っている）

### E-5/E-6. 個別の数値不整合

### 2026-07-25 第2階層：ボーナスビートの導入（B-3 / B-4 / B-5）

**判明した前提の訂正**

到達不能だった45件は配置ミスではなく、**存在しないビート用に書かれたコンテンツ**だった。stage 1＝到着シーン、stage 5＝昼食、stage 9＝ラウンド後で、9ホール構成にはそのいずれのビートも無い。したがって当初案の「stage を出やすさの重みに変える」では救えない（「駐車場で相手と合流」がホール3で発生してしまう）。

**採用した方式：ボーナスビート**

ラウンド開始時に3種から**1つだけ**抽選し、そのビートだけを挿入する。ホールを消費しないので **9ビート → 10ビート**。

| ビート | 挿入位置 | 消費するstage | プール |
|---|---|---|---|
| `pre` | 朝イチのショットの前 | 1 | 16件（駐車場・ロッカー・練習グリーン・スタート待ち等） |
| `lunchTalk` | キャラ別ランチイベントの後 | 5 | 20件（昼食・酒・午後スタート前） |
| `closing` | 最終パットの後 | 9 | 16件（風呂・表彰・プロショップ・別れ・見送り） |

**実装**
- `GameState` に `bonusBeat` / `bonusBeatDone`、`GameEvent` に `beat?` を追加
- `engine.applyChoice`: `event.beat` が付いたイベントはホールを消費しない。`closing` はラウンド最終ビートなのでここで終了する
- `engine.applyChoice`: ホール9を終えるとき `closing` が控えていれば完了を保留し、締めを1ビート挟んでから終了する
- `engine.selectEvent`: `pre` / `closing` の抽選を追加
- `engine.selectLunchTalkEvent`（新規）: ランチはホール5で席選び→メニュー→キャラ別イベントという独自フローを持つため、ホール番号ではなく `GameScreenSimple` の lunch サブフェーズから明示的に呼ぶ
- 相談ラウンド（ACE）は独自フローなので `bonusBeatDone: true` にしてビートを発生させない

**ビートの意味に合わせたイベント再配置（9件）**
