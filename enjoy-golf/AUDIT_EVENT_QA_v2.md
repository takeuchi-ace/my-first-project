# イベントテキスト再監査レポート（第2版）

**作成日**: 2026-07-25
**対象**: enjoy-golf 全イベントデータ（現行）
**ステータス**: レポートのみ（コード変更なし）
**前版**: `AUDIT_EVENT_QA.md`（2026-02-22）

## 監査方法

1. イベントデータ全ファイルを精読（events / curated / character / lunch / female / extreme / goodBack / tensionBack / ace / competition / morningShot / putting）
2. データを実際に require し、本番と同じ経路（`applyChoice` → trait補正 → キャラreactions → likes/hates → クランプ → `evaluateReactionRank`）で全1,160選択肢 × 21キャラをシミュレーション
3. 到達可否・重複・tag被覆・選択肢位置の偏りを機械集計

**未実施**: 実機プレイによる目視確認。表示崩れ・演出タイミングは本レポートの対象外。

## E. ロジック不整合 — 優先度: 中

### E-1. 最終パットの「誤ったアドバイス」が機能しない

`puttingEvent.ts` は `adviceAccuracy` で正誤を振り分けるが、誤アドバイス時の文言が傾斜によって分岐していない:

- `ONIZUKA_PROFILE`: 誤アドバイスは常に「右に外してみては！勢いで決めろ！！」
- `GENERIC_PROFILE`（19キャラ）: 誤アドバイスは常に「右に外してみてはどうでしょう」

ところが slope `left` の `correctAim` は `right`。**傾斜が左のとき、誤アドバイスがそのまま正解になる**。鬼塚と汎用19キャラ、つまり20/21キャラで読み合いが成立しない。`TANAKA_PROFILE` は傾斜ごとに分岐しており問題なし。

### E-2. creep が二つの意味で使われている

本来「気持ち悪さ／距離感の失敗」を表すゲージだが、「場を冷やした」ペナルティとしても流用されている:

- 「…」と黙る → creep +9（`char_13_2`）
- 無言で目をそらす → creep +9（`char_10_5`）
- 「時間大丈夫ですか？」 → creep +8（`char_3_1`）
- 「科学的根拠はあるんですか？」 → creep +10（`char_6_5`）

プレイヤーには「なぜ黙ったら気持ち悪がられるのか」が伝わらない。ゲージ名と体験の乖離。

### E-3. worst の発生率が高い

| ファイル | worst率 |
|---|---|
| lunchEvents | 48.2% |
| tensionBackEvents | 47.8% |
| femaleEvents | 42.4% |
| characterEvents | 41.4% |
| events.ts | 23.6% |

キャラ固有・ランチという「そのキャラらしさが出る場面」ほど、選択肢の4割が最悪反応になる。

### E-4. 宣言済みtag 43種のうち4種が未使用

`self_suppress` `over_adjust` `over_flatter` `forced_laugh`（キャラ側の `reactions`/`likesTags`/`hatesTags` からも参照されていないため、実害はないが定義だけ残っている）

### 2026-07-25 難易度の設計：タグ減衰と trust の自然減

「極端が相手次第で正解」を入れた結果、**刺さる型を掴んだら同じ手を押し続けるのが最適**になる懸念があった。その対策としてタグ反応の減衰を実装したが、測ってみると難易度のツマミではなかった。原因を追ったところ別の構造問題に行き着いた。

**1. タグ反応の減衰（実装済み・保険として維持）**

同じタグを1ラウンド内で繰り返すと、そのタグに対する相手の「喜び」が鈍る（1回目100% → 2回目70% → 3回目45% → 4回目以降25%）。

- 減衰するのは `reactions` の**正の反応**と `likesTags` ボーナスだけ
- `choice.delta`（行為そのものの効果）は減衰しない
- `hatesTags` の罰と負の反応は減衰しない（嫌なことを繰り返されて慣れる相手はいない）
- `tagHistory` はラウンド単位でリセットされるので効果もラウンド単位

**実測では効果が小さかった**（最良選択プレイの score 96.8 → 96.0、契約成功率 99.9% → 99.8%）。理由は、熟練プレイは同じタグを連打しないため。イベントごとに最良を選ぶとタグは自然に散る。想定した「同じ手を押し続ける」打ち方自体が発生しない。退化した戦略への保険としては意味があるので残した。

**2. 難易度が上がらなかった本当の理由**

最良選択プレイでは **trust が3〜4ビート目で閾値70に到達する**（74%のラウンド）。

| 到達ビート | 割合 |
|---|---|
| 2ビート目 | 11% |
| 3ビート目 | 43% |
| 4ビート目 | 31% |
| 5ビート目 | 13% |

10ビートのうち最初の3〜4手で契約条件が確定し、残りは結果に影響しない。trust は上限100に張り付くので、閾値を92まで上げても熟練プレイは100%のままだった。

**3. trust の自然減（採用した対策）**

`Character.trustDrift` を新設。1ビートごとに trust が目減りするため、ラウンド全体で稼ぎ続ける必要がある。

| drift | キャラ |
|---|---|
| 2（序盤・ノリで許す） | 田中・鬼塚・坊っちゃん・光山・松本・星野・ミツキ |
| 3（標準） | スミス・巌・中村・金城・千鶴・篠原 |
| 4（手強い） | 黒田・佐藤・大門・白石・桐生・早瀬 |
| 5（最難） | 鷹宮 |
| 0 | ハジメ（相談ラウンドはゲージを使わない設計） |

**落とし穴**: 目減りをそのまま入れると、画面がゲージの前後差から反応ランクを算出しているため毎回 trust −3 が混ざってランクが下振れする。`GameState.lastAppliedDelta`（目減り前の反応そのもの）を `applyChoice` が記録し、ランク判定はそれを使うようにした（`GameScreenSimple` / 旧 `GameScreen` の両方を差し替え）。

**難易度カーブ（実測）**

| 最良を選べる確率 | 変更前 | 変更後 |
|---|---|---|
| 100%（理論値） | 100% | 97.6% |
| 80% | 95% | 83.8% |
| 60% | 85% | 62.3% |
| 40% | 71% | 42.9% |
| 0%（ランダム） | 38% | 13.1% |

creep爆発も機能を維持（ランダムプレイで3.4%）。

**キャラ差は drift だけでは決まらない（既知の課題）**

腕前60%での実測では drift 別平均が 2→58% / 3→70% / 4→55% / 5→51% と単調にならない。難易度を支配しているのは drift より「そのキャラの `reactions` に高 trust の受け皿が何個あるか」だった。

- **大門は16%と突出して難しい**。`reactions` が4つしかなく正の反応は `honesty` +3 だけなので、どの選択肢を選んでも trust が伸びない。意図した難しさではなく設計の穴
- 逆に早瀬は drift-4 でも87%（`honesty` +6 / `logic` +5 と受け皿が広い）

`trustDrift` は全体を押し下げるツマミとしては機能するが、キャラ個別の難易度を作るには `reactions` の設計も併せて触る必要がある。大門の `reactions` 拡充は別作業とする。

| | 変更前 | 変更後 |
|---|---|---|
| セリフ | 本音 | 建前（正反対のランクの言葉） |
| 仕草 | 偽物（クラス反転） | 本音（真のランク） |
| 表情 | 本音 | 本音（変更なし） |

建前のセリフは書き下ろさず、`MASK_RANK` で**正反対のランクの既存セリフを流用**する。口調が絶対に崩れず、curated イベントでは選択肢ごとの専用セリフがそのまま建前として機能する（good を隠すと「…お世辞はいらないです。」が出る）。`mismatchSpeechLines` は最優先の上書きとして配線してあるので、個別に書きたくなったら書けば効く。

あわせて:
- 隠すターンは**仕草を必ず表示**（従来70%。唯一の手がかりなのに出ないことがあった）
- 隠すターンの仕草を金色・太字にして、言葉と食い違うサインにした
- 見抜き判定を「隠されたターンの**次の一手**で正解を選べたか」に変更。隠されたターン自体はまだ何も見ていないので運でしかなかった
- 3連続で **ACEボール +1**（`store.gainAceBall`、上限2）。人を読める人は失敗を取り返せる、という筋

**2. ミニゲームの結果を engine 経由にした**

朝イチの自分のショットと最終パットの delta が画面側で直接 clamp されており、`traitModifiers` が効かず「誰が相手でもパットインは trust +5」だった。`applyMinigameResult()` を追加して選択肢と同じ補正経路に通した。

```
パットイン（素の値 trust+5）
  佐藤 1.4 → +7  ／ 田中・巌・桐生・鷹宮・早瀬 1.3 → +7
  黒田・スミス・白石 1.2 → +6  ／ 大門・ハジメ 1.0 → +5
  鬼塚・光山・星野 0.8 → +4（その分 fun が増える）／ 松本 0.7 → +4
```

`trustDrift` はここでは引かない。ミニゲームは同じビートの一部で、ホール分の目減りは `applyChoice` 側で引かれているため。

**3. focus ゲージに役割を与えた**

focus は選択肢で頻繁に上下するのに、勝敗に一切絡んでいなかった（`entertainScore` も `contractSuccess` も trust/fun/creep のみ）。4つあるゲージの1つが実質飾りだった。

**ミニゲームの判定窓の広さ**に接続した。接待に振り切って自分のプレーを疎かにすると、朝イチも最終パットも決まらなくなる。

| focus | 倍率 | 朝イチPERFECT幅 | パットPERFECT幅 |
|---|---|---|---|
| 0 | 0.60 | 12% | 6% |
| 50（初期値） | 1.00 | 20% | 10% |
| 100 | 1.40 | 28% | 14% |

判定と目標ゾーンの描画を**同じ数値から生成**しているので、集中力が落ちるとゾーンが目に見えて狭くなる。新しいUIを足さずに伝わる。

**副産物のバグ修正**: パットの目標ゾーンは表示が 40–60%（朝イチと同じ幅）なのに実判定は 45–55% で、**見た目と判定が食い違っていた**。同じ数値から作るようにしたので解消した。

**検証**: `tsc --noEmit` 通過。ブラウザ実機で focus 50 のときゾーンが PERFECT 20% / GOOD 40%（従来と同一）であることを確認。

## E-2 creep ゲージの二重の意味（4点目）

creep は「相手に引かれた度合い」を1本で表しているが、引かれ方には3種類ある。終了時の文面はこれを言い分けていなかった。

### 帰属の誤り

`attributeCreep()` はプレータイプ診断用の `TAG_GROUPS` を流用していた。そのため `serious`（honest群）と `logic`（dominant群）がどの判定にも当たらず、既定の「詰めすぎ」に流れ込んでいた。

creep を持つタグを全データで集計した結果:

| タグ | 選択肢数 | creep合計 | 平均 |
|---|---|---|---|
| serious | 116 | **270** | 2.3 |
| logic | 104 | **125** | 1.2 |

この2タグだけで creep 395 分＝冷たさ由来の約3分の1。正論を並べて引かれた結果が「距離を詰めすぎて引かれた」と表示されていた。

診断用の群とは目的が違うので、`CREEP_SOURCE_TAGS` を別に持たせて creep 本来の意味（引かれ方）で切り直した。

- `cheat` : cheat / cheat_score / cheat_physical / snitch
- `distant` : silence / distance / **serious** / **logic** / neutral / safe / safe_play / avoid_risk / excuse / self_suppress
- `close` : 上記以外（creep の既定の意味）

### 「壁を作られたまま終わってしまった」が発生しない問題

帰属を直した結果、この文面が**実質使われない**ことが判明した。冷たい選択だけで通すと creep は 49〜67 で止まり、100 に届かない。

| | 契約成功 | 平均trust | 平均creep | creep爆発 |
|---|---|---|---|---|
| 冷たく徹する | 16.1% | 44 | 35 | **0.1%** |
| 詰めすぎる | 11.7% | 26 | 67 | 33.6% |

冷たいプレーは失敗するが、**trust が積めないという別経路**で失敗していた。creep 爆発の文面としては死んでいた。

**1回ごとの creep を上げるのは却下した。** それだと慎重に距離を取る1手まで罰することになり、「無難」が常に地雷になる。

代わりに**罰を連続に乗せた**。壁は1回では立たない。

```
COLD_WALL_CREEP = [0, 0, 0, 3, 5, 7, 9]   // index = 連続回数
```

3回目から効き始め、6回目以降で頭打ち。好みへのボーナスが繰り返しで鈍る（`tagDecayRate`）のと対になる形。**そのキャラが好むタグは壁に数えない**（黒田の `serious` など）。相手が望む距離感を守っているだけなので連続が途切れる。

### 結果

冷たさで終わる失敗が成立し、かつキャラごとに違う。

| キャラ | 冷たさcreep | 最終creep | 途中終了率 | 嫌う冷タグ |
|---|---|---|---|---|
| 金城 | 82 | 86 | **37%** | safe, silence |
| 松本 | 78 | 83 | **38%** | serious, silence |
| 坊っちゃん | 80 | 86 | **33%** | serious, logic |
| 星野 | 59 | 76 | **27%** | serious |
| 鬼塚 | 70 | 78 | **20%** | safe, silence, avoid_risk |
| 光山 | 70 | 76 | **20%** | serious, silence |
| 黒田 | 9 | 17 | 0% | —（沈黙を好む） |
| 中村・白石 | 9 | 14 | 0% | — |

寡黙なプロ・黒田に無言で付き合うのは壁にならない。褒め殺し王・松本に正論で返し続けると壁になる。全体の途中終了率は 8.4%。

判定文の内訳も意図通りに出るようになった（冷たく徹したとき `tooDistant` 100%、ランダムプレー時 cheat 23% / tooClose 74% / tooDistant 3%）。

### 回帰

| 腕前 | 契約成功 | 平均score | creep爆発 |
|---|---|---|---|
| 100%（正解を引き続ける） | 97.5% | 93.5 | 0.0% |
| 80% | 81.0% | 88.3 | 0.0% |
| 60% | 62.5% | 81.6 | 0.1% |
| 40% | 42.4% | 73.9 | 0.1% |
| 0%（ランダム） | 13.7% | 56.9 | 2.8% |

難易度曲線は維持。普通のプレーは壁の罰を踏まない（3連続で冷たい選択を選ばないため）。共通プール到達 167/167（superseded 3件を除く全件）、ハング 0 / 4200 ラウンド、`tsc --noEmit` 通過。

### 監査時の15件はすでに解消していた

キャラが反応を持つタグを集計すると、偏りが極端だった。

平坦だったイベントは軒並み `safe` / `neutral` / `over_support` / `etiquette` だけで組まれていた。`opponent_ball_mark` は3択とも `etiquette` で、何を選んでも同じになるのは当然だった。3択が別々の反応を持つタグを踏むように組み替えた。

### 測定中に見つけた、より重い問題：逃げ場のない局面

**3択すべてが worst になる組み合わせが18通りあった。**

## D-5 extreme の文体が固定テンプレ

delta 側（creep 12〜18）は極端リバランスで対処済み。残っていたのは文体。

### events.ts 側は「絶叫」1種類しかなかった

extreme タグ付き58件を並べると、ファイルで完全に二分されていた。

- **events.ts の39件** — 40〜73字、全部が同じ構造

  ```
  「[称賛]！！[もっと大きい称賛]！！[過剰な行動宣言]！！！」と[ト書き]
  ```

  語彙も集中していた: 神/ゴルフの神 5件、伝説 4件、記念碑・銘板・本・雑誌の表紙 5件、「今すぐ」4件、「〜してください（弟子に/祀らせて/呼ばせて）」4件

- **extremeEvents.ts の19件** — 8〜27字、淡々（「黙ってすり替える」「無言でスマホを見始める」「その情報を他の人脈に流そうと考える」）

つまり共通プール側には「冷たい極端」「無言の極端」「打算の極端」が一切なかった。**削るのではなく型を増やす**方針で、delta とタグは1つも変えずに書き換えた。

| 型 | 件数 | 例 |
|---|---|---|
| 低温型（真顔で、静かに） | 5 | 「…すみません、少し黙らせてください。今の一打、言葉にすると軽くなるので」と帽子を取って立ち尽くす |
| 執拗型（質問と確認が止まらない） | 5 | 「左です。左しかない。左に賭けます。もし右に切れたら自分が謝ります。左です」と繰り返す |
| 過剰準備型（もう済ませてある） | 4 | 「全ホール記録してあります。パーオン率、フェアウェイキープ率、平均パット数。製本してお送りします」と資料を出す |
| 短い断言型 | 16 | 「惜しい、じゃないです！！事件です！！」と言い切る |
| 絶叫型（従来） | 11 | 「ここ一番！！○○さんの見せ場です！！ギャラリーが息を止めてます！！」と全力で盛り上げる |

### 途中で手掛かりを強くしてしまった

長文を圧縮した段階で測ると、**45字以上の最悪率が 50% → 68%、「！！」が 45% → 54% に悪化**していた。穏やかな極端（誰かに刺さるもの）を短く直したため、長く騒がしい枠に厳しいものだけが残る選択効果を自分で作っていた。

原因を見ると、長文枠を占めていたのは `over_support`（過剰な世話）と `cheat_score` で、これらは設計上「誰にも刺さらない」ものだった。長さと無関係に短くも書けるので圧縮した。

さらに「！」を落としすぎて 58件中3件（5%）まで減り、絶叫型がほぼ消えた。派手さを削らない方針に反するので、**good になる極端の側に派手さを戻した**。

- ノリを好む5人（光山・松本・星野・篠原・ミツキ）に刺さる極端 → 最も騒がしく書く
- 巌・千鶴に刺さる極端（控えめな持ち上げ・礼を尽くした辞退） → 静かなまま

派手さが「地雷の目印」から「相手の好みの表現」に変わった。

### 結果

| 見た目の手掛かり | 件数 | イベント内最悪率 | good率 |
|---|---|---|---|
| 「！！」を含む | 16 | 45% → **13%** | 7% → **17%** |
| 45字以上 | 9 | 50% → 44% | 6% → 7% |
| 「！」なし | 473 | 29% → 31% | 15% → 14% |

（3択なら33%が偶然の水準。監査時点の「！！」は77%だった）

**「！！」は最悪率が偶然を大きく下回り、good率は平均を上回った。** 派手な選択肢は、平均すると外れより当たりが多い。

決定的な確認として「派手な選択肢は読まずに避ける」戦略を回した。

| 腕前 | 通常プレー | 派手を避ける | 差 |
|---|---|---|---|
| 100% | 98.0% | 97.6% | **-0.4pt** |
| 80% | 82.6% | 81.4% | **-1.2pt** |
| 60% | 61.8% | 61.0% | **-0.8pt** |

見た目で避ける戦略は、どの腕前でも損になった。手掛かりとして死んでいる。

| 腕前 | 契約成功 | 平均score | creep爆発 |

| 100% | 98.0% | 93.5 | 0.0% |

## コンペラウンドのバグ調査

### 実機で再現した症状

春の名門オープンを trust 100 / rep 100 で勝ち切った直後の保存データ。

| 項目 | 期待 | 実際 |
|---|---|---|
| `competitionCleared` | `{springOpen:true}` | **`{}`** |
| `unlockedCharacterIds` に篠原(17) | 含まれる | **含まれない** |
| `contractedCharacterIds` | `[1]` | **`[1,17]`** |
| `totalContracts` | 1 | **2** |
| 誤って解放されたキャラ | なし | **ミツキ(21)** |

画面には「篠原さんとの通常ラウンドが解放されました！」と出るのに、**篠原は解放されず、代わりにミツキが解放される**。コンペのクリアも記録されないので何度でも繰り返せる。

### 原因1: スナップショットでの全体置き換え

`useGameStore` の `addContractForCharacter` だけが、唯一 `setState((prev) => ...)` ではなく `stateRef.current` のスナップショットで**状態全体を置き換えていた**（他は全て関数形。例外は意図的な全リセットのみ）。

`stateRef.current = state` はレンダー時代入なので、同じ tick で2つ呼ぶと2つ目が1つ目の更新を消す。結果画面は次の順で呼んでいた。

```ts
store.markCompetitionCleared(competitionId);           // setState((prev) => ...) で積まれる
store.addContractForCharacter(result.targetCharacterId); // 古い state で全体を上書き → 上が消える
```

**同じ被害が通常ラウンドにも出ていた。** `ResultScreenSimple` は契約成立時に `incrementRoundCounter()` → `handleRoundComplete(characterId)` → `addContractForCharacter(characterId)` の順で呼ぶため、**契約が取れたラウンドではラウンド数の加算とクールダウンの設定が消えていた**（コンペの解放が遅れ、契約した相手をすぐ再プレーできる）。

更新を関数形に変えた。戻り値（解放演出に渡すリスト）は従来どおり呼び出し時点の値から求めている。

### 原因2: コンペのクリアで契約が付いていた

対象キャラの解放条件は `competitionClear` なので、`markCompetitionCleared` だけで解放は足りる。`addContractForCharacter` は解放に不要な上、1度も回っていない相手が契約済になっていた。

- 契約数が水増しされ、`totalContractsAtLeast: 5` の銀座ハジメが3件ぶん早く解放される
- `contractWith: 17` のミツキ、`contractWithAny: [21,18]` の早瀬が誤って解放される
- 一覧に「契約済」と嘘が出る

`unlockText` が「通常ラウンドが解放されました」と書いている通り、コンペは解放であって契約ではない。呼び出しを削除した。

### 原因3（原因1を直して露出）: 解放メッセージが即座に消える

`isFirstClear` を毎レンダー `store.isCompetitionCleared()` から計算していた。クリアを記録した瞬間に `false` になり、これを表示条件にしている解放メッセージが消える。

**このバグは以前から存在したが、原因1に隠れていた**（クリアが記録されないので `isFirstClear` が `true` のままだった）。同画面の他所と同じく `useRef` で初回値を固定した。

| 経営者杯 | 82 | 0/81 |

仕組みを足しても到達しないコードになるため入れていない。あわせて分かったこととして、`calcCompetitionResult` の `creep <= 85` は春の名門（最大20）と経営者杯（最大82）では常に真で、実質シーサイドチャリティ専用の条件になっている。

|---|---|---|

| 経営者杯 | 27/81（33%） | 26/81（32%） |

難易度は下がっていない。`tsc --noEmit` 通過。

**判断: 引かれ度の条件は現状のまま据え置く（2026-07-29 確認済み）**

`calcCompetitionResult` の成功条件は「信頼度 ≥ 閾値」「評判 ≥ 閾値」「creep ≤ 85」の3つだが、3つ目は3コンペのうち2つで原理的に満たされてしまう。

| コンペ | creep 最大値（全81通り） | 85を超える組み合わせ |
|---|---|---|
| 春の名門オープン | 20 | 0/81 |

| シーサイドチャリティ | 97 | 2/81 |

つまりコンペで負けるときは必ず「信頼度か評判が足りない」で負け、「引かれすぎて嫌われた」という負け方はほぼ存在しない（シーサイドチャリティの2通りのみ）。通常ラウンドの creep 爆発に相当するものがコンペには成立していない。

### 見つかった問題

**1. ポップアップの文字が読めなかった（重要）**

`aceBallPopup` の背景が `COLORS.cardBg`（8%の白）でほぼ透明だったため、後ろのセリフと仕草が透けて文字が重なっていた。貴重なボールを使うか決める場面で判読できない状態だった。不透明な板（`#14301f`）＋影に変更。

**2. やり直しても、取り消した選択のペナルティが残っていた（重要）**

`updateTanakaState` / `updateOnizukaState` はモジュール変数を加算するだけで、`GameState` に入っていないため `previousState` では戻らない。結果、ACEボールで選択を取り消しても次が残っていた。

- 媚びスタック（`flatterStack >= 3` で fun 倍率 0.7、`>= 5` で気合の要求が上がる）
- **不正カウント（`cheatCount === 0` が S 評価の条件）** — 不正を取り消しても S 条件が壊れたまま
- 洞察の連続数（`insightStreak`）と直前のミスマッチ判定（`prevWasMismatch`）

`snapshotTanakaState` / `restoreTanakaState`（鬼塚も同様）を追加し、選択の直前を控えて「やり直す」で復元するようにした。田中の8項目すべてが戻ることを確認。

```
鬼塚: 媚び2回 → fun倍率 1.0
      媚び3回 → fun倍率 0.7
      やり直し → fun倍率 1.0   ← 戻る
田中: 不正1回 → cheatCount 1
      やり直し → cheatCount 0  ← 戻る（S条件が復活）
```

影響を受けるのは田中と鬼塚だけだが、この2人は最初に出会うキャラクター。

**3. ボール獲得の判定が `setState` の実行タイミングに依存していた**

```ts
const gainedRef = useRef(false);
const gainAceBallFn = useCallback(() => {
  gainedRef.current = false;
  setState((prev) => { ...; gainedRef.current = true; ... });
  return gainedRef.current;   // ← 更新関数がまだ走っていない可能性
}, []);
```

React は `setState` の更新関数を必ず同期実行するわけではない（同じ tick に他の更新が積まれていると遅延する）。その場合ボールは増えるのに `false` が返り、**獲得の演出（`showInsight`）が出ない**。同期的に読める `stateRef` で判定するように書き換えた。

**4. バッジが朝イチ／最終パットの画面だけ消えていた**

ACEボールのバッジは通常イベントと昼の画面にはあるが、朝イチのショットと最終パットの画面には無く、ビートをまたぐたびに現れたり消えたりしていた。両方に足して統一。

- ポップアップの「残り: n個」は使用前の数を出している。「やり直す」を押すと n-1 になる。表記としては正しいが、押す前に減った数を見せたい場合は要調整

### 検証

### 眠っていた文章資産の配線（ステップ3）— `reactionLines` 170行と `role`

**`reactionLines` は何だったのか**

型は「セリフ」と読めるが、中身を全件見ると**地の文（ナレーション）**だった。

```
reactionLines: 「黒田の視線が厳しくなった。」   ← 描写
セリフ側:      「…違う。」                     ← 本人の言葉
```

実測: 全170行のうち **157行（92%）が「。」で終わる完全な文**、36行（21%）が中に「」を含む。
つまりセリフ枠には入らない。行き先は既存の**仕草枠**（これまで全キャラ共通の汎用30件だった）。

**混ぜ方の判断**

最初はキャラ別を優先する形にしたが、測ると副作用が出た。

| 方式 | キャラ別の採用率 | 1キャラ1ランクの文の種類 |
|---|---|---|
| キャラ別を優先 | 100% | **2種**（汎用30件が全部出番を失う） |
| 単純に足し合わせる | 17% | 12種（キャラ別がほぼ出ない） |
| **確率60%でキャラ別**（採用） | **60%** | **12種** |

キャラ別だけにすると、死んだ資産（170行）を活かす代わりに別の資産（30行）を殺し、
しかも同じ文が2種で回るので繰り返しが目立つ。`NARRATION_RATE = 0.6` で両方を残した。
実測 19,088回で キャラ別 60% / 汎用 40%、文の種類は 10 → 12 種に増えた。

**建前ターンの「」二重問題**

本音を隠すターンは、吹き出しが建前・地の文が本音になる。地の文の21%が「」を含むため、
そのまま出すと画面に鍵括弧が2組並び、**仕込んだ食い違いではなく文章の破綻に見える**。
隠すターンだけ「」を含む行を除外した。実測 4,841回の建前ターンで二重発生 **0件**。

**表示形式**

地の文は完結した文なので、汎用の仕草のように `*…*` で囲むと不自然になる。
`ReactionPlan.gestureIsNarration` を足して表示側で分岐した。実機で両方確認:

- 地の文 → 「田中の眉が少し寄った。」（囲みなし）
- 汎用 → 「\*クラブを軽く掲げた\*」（囲みあり）

**`role`**

`hint`（攻略の助言）とも `targetHint`（好みの示唆）とも別の、性格そのものの一文。
プロフィール画面の座右の銘の下に置いた。実機確認: 田中で「堅実で数字に厳しい。誠実さを重んじる。」

**回帰**: 契約成功率 98.6 / 81.7 / 62.5 / 41.9 / 12.2%（前回 97.8 / 82.3 / 64.2 / 42.5 / 12.9）、
共通プール到達 167/167、ハング 0 / 4200、空文字の仕草 0件、`tsc --noEmit` 通過。

#### 動かなかった理由（配線前の測定）

| 測ったこと | 結果 |
|---|---|
| 摩耗が上がるタグ4つ（`self_suppress` `over_adjust` `over_flatter` `forced_laugh`）の使用数 | **選択肢1,034件中 0件** |
| 摩耗が下がるタグ（`honesty` `sportsmanship`）の使用数 | 174件 |
| そのまま配線した場合 | 初期値10から下がる一方で0に張り付き、永久に何も起きない |

既存タグ（おだて・絶賛・過剰な世話・沈黙・無難＝上げ／正直＝下げ）に読み替えても動かなかった。

| プレイの型 | 1ラウンドの摩耗 | 20ラウンドで40に届くか |
|---|---|---|
| 勝つ手を選び続ける | −4.9 | 届かない |
| 正直に寄せる | −7.1 | 届かない |
| おだて一本（契約成功39%） | +8.8 | 9ラウンド目 |

「勝ちながら摩耗する」のは 4/21人だけ。21人と契約する一周では一度も0から動かない。

**より本質的な問題**: 摩耗が上がる選択の creep 平均は **7.71**、下がる選択は 0.03（相関 r=0.445）。
creep の遅い二重版であり、動くときは既に負けているプレイヤーを追い打ちするだけだった。

#### 再設計 — creep と別の軸にする

```
creep = 相手が引いた       （やりすぎ・相手視点・1ラウンドで完結）
摩耗  = 相手に合わせて通った （自分を殺した・自分視点・ラウンドを越える）
```

**迎合して失敗したときは加算しない**。そこは creep の担当なので、二重に罰さない。
「通った迎合」だけを数えると creep との相関は **r=0.445 → 0.076**、
摩耗が上がる選択の creep 平均は **7.71 → 1.27** に落ちて別の軸になった。

溜まるタグ: `silence` +3 / `over_praise` +3 / `flattery` +2 / `over_support` +2 / `safe` +1

沈黙を最も重くしたので、**寡黙な黒田（+4.8）や重鎮の巌（+4.2）の前でも勝ちながら摩耗する**。
言葉を飲み込み続けるから。褒め殺し王の松本が +10.8 で最大、本音で当たれるミツキ・大門・桐生は +0.4〜0.8。

#### 回復量の決め方 — 逃げ道が無いと一方通行の数字になる

固定 −1 だと、摩耗45から本音で当たれる相手を12ラウンド回っても 43〜48 を行き来して下がらなかった。
逆に「迎合2以下で −5」にすると、今度は一周しても最大18でしきい値25に届かない。
5案を測って、両方成り立つ幅は1つだけだった。

```
そのラウンドの迎合が 1 以下 → -3（自分を出せたラウンド）
それ以上              → -1
相談ラウンド          → -15
契約成功              → 回復させない
```

契約で回復させないのは、迎合で勝った代償を勝利そのものが打ち消してしまい
「接待で勝つことには値段がある」という前提が崩れるため。

**実測（25ラウンドのキャリア×3000）**

| | 到達した最大摩耗の中央値 | 25以上に届く | 35以上 |
|---|---|---|---|
| 上手いプレイ | 41 | 86% | 66% |
| ほどほどのプレイ | 34 | 77% | 49% |

- 摩耗45から本音で当たれる相手を10ラウンド回ると **27** まで下がる（逃げ道が機能）
- 松本を連戦すると 20 → 70（6ラウンド）
- しきい値は 25 / 35。45に置くと到達が 42%／23% に落ち、強い内なる声3行と創業者の一言が半分以上に読まれない

creep と重なる罰（mismatch率上昇・スコア −5%・洞察の抑制）は**入れなかった**。
同じ行為に2つのゲージが反応するだけになるため。該当する3関数は削除した。

  何に対する声か分からないが、直後に出せば隠しパラメータのまま原因と結果が結びつく。
  実測 摩耗25で0.33回／ラウンド、35以上で0.58回。摩耗0では出ない。
- **創業者の気づかい** — 相談ラウンドで、摩耗している相手にだけ答える前に一言添える（1ラウンド1回）

自分を殺した記録だけが積まれる（`6299e33` で直した媚びスタック・不正カウントと同じ穴）。

### C-5 の入口 — 最終パットが「判定として壊れていた」

「相手の返事が噛み合わない」を最も出番の多い選択肢から埋める作業に入ったところ、
最終パットは文章の問題ではなく**判定そのものが成立していなかった**ことが分かった。

#### 見つけたもの

狙いを決めた直後の反応ランクを全通り（21キャラ×4傾斜×正誤2通り×3択＝504通り）測った結果:

| | good | neutral | bad | worst |
|---|---|---|---|---|
| 改修前 | **0%** | 3% | **94%** | 3% |

3択とも delta が `{ focus: 1 }` だけで trust が動かないため、
反応判定が一律「悪い選択」と読む。**自分のパットの狙いを決めただけで、
相手が毎ラウンド不機嫌な顔と否定的なセリフを返していた**。しかも good は到達不能。

参考に朝イチのショット（相手のショットへの反応＝本来の社交的な選択）は
good 31% / neutral 33% / bad 13% / worst 23% で健全だった。壊れていたのはパットだけ。

#### 直し方 — 3択に社交的な意味を持たせる

この場面の本来の緊張は「相手の読みが外れているとき、**おもねるか、逆らって入れに行くか**」。
その受け止め方は相手によって変わるべきで、そこは既存の `likesTags` / `hatesTags` / `reactions`
がそのまま担える。3択を意味で分けた。

| 選択 | 意味 | delta | tags |
|---|---|---|---|
| 相手の読みに乗る | 顔を立てる（おもねる） | trust +3 / fun +2 / focus +1 | `etiquette` `flattery` |
| 自分で正しい線を読む | 相手の読みを退ける | trust +2 / focus +2 | `honesty` `bold` |
| どちらでもない | 誰の読みでもない場所 | trust −1 / focus +1 | `safe` |

**結果（助言が外れているとき）**

- おもねるのが正解 **5人**（巌・千鶴・光山・ナイス松本・篠原）
- 逆らうのが正解 **12人**（田中・黒田・中村・佐藤・桐生・鷹宮・早瀬 ほか）
- どちらでも同じ 4人

松本は助言が **70%外れる**うえに逆らうと機嫌を損ねる、という組み合わせになった。

反応ランクは good 10% / neutral 22% / bad 50% / worst 17%。
bad が多いのは3択のうち2つが「誰の読みでもない場所」になる局面（助言が当たっている場合）が
あるためで、狙いを外した選択が罰されるのは意図通り。

#### セリフ（12行）

汎用テンプレは「何を選んだか」を見ないので、この場面用に書いた。
`getPuttAimReply(followedAdvice, rank)` で、乗ったか逆らったか × 反応の良し悪しで引く。

```
従う good    → 「そう、そこです。」「信じてもらえましたね。」「ええ、そのラインです。」
従う bad     → 「…言われた通りに、ですか。」「自分の目は、使わないんですね。」
逆らう good  → 「…自分で読みましたか。いい目だ。」「なるほど、そう見ましたか。」
逆らう bad   → 「…私の読みが、信用できませんか。」「そうですか。ご自由に。」
```

#### 難易度の調整

パットで trust が動くようになった分、放っておくと易しくなる。
閾値通過率（契約成功率）は測定のばらつきが ±2 あって判定に使えないため、
連続量（最終 trust の平均・スコアの平均、21キャラ×200ラウンド）で比較しながら詰めた。

| 案 | trust差（技能0.8 / 0.4） | 割れ方 |
|---|---|---|
| 従3・逆2・他 focus のみ | +1.79 / +1.09 | 5/12/4 |
| 従3・逆2・**他 trust−1**（採用） | **+1.49 / +0.49** | 5/12/4 |
| 従3(fun削除)・逆2・他 trust−2 | +1.02 / +0.18 | 5/12/4 但し good が 32%→10% に痩せる |

「誰の読みでもない場所」にだけ罰を置くと、割れ方を保ったまま甘さを半分に戻せた。
残る差は **trust +1.5（100点満点中）**。パットに社交的な重みを持たせた以上ゼロにはできず、
これ以上削ると反応の良し悪しの分布が痩せるため、ここで止めた。**難易度は下げていない。**

**回帰**: 共通プール到達 167/167、ハング 0/4200、相談ラウンド 200/200、`tsc --noEmit` 通過、
コンソールエラーなし。

**検証の限界**: 最終パットは9ホール目のため、この環境では実機到達できていない。
判定・セリフとも本番と同じ経路（`buildPuttingGameEvent` → `applyChoice` → `evaluateReactionRank`）で確認した。

### 周回プレイのゲームバランス調査 — イベント増設は不要、難易度の偏りは意図的に残す

「全クリまで周回が必要だが、同じキャラで同じ選択肢に飽きないか」「難易度はどうか」を測った。

#### イベント数は足りている（増設不要）

| | |
|---|---|
| 全21人と契約するまでの周回数 | **26**（技能0.8）／**36**（0.6）／**59**（0.4）ラウンド |
| その間に各キャラを回す回数 | 平均1〜3回 |

| 3周目 / 5周目 / 10周目 | 66% / 55% / 42% |

#### 難易度の分布（ほどほどのプレイヤー・各400ラウンド）

契約成功率が **20%〜95%** に散らばっている。

```
最難  大門 20% / 松本 43% / 星野 45% / 光山 49% / 黒田 49%
最易  中村 78% / 千鶴 86% / 早瀬 86% / 田中 93% / ハジメ 95%

好み `bold + logic` が**同じ選択肢に同居しない（0件）**ため、両方満たす手が存在しない。

なお「好みのタグ2つが同居0件」は8人が該当（スミス・佐藤・大門・白石・篠原・桐生・鷹宮・ミツキ）で、
その8人の成功率は50〜72%。**0件そのものが原因ではなく**、
大門は「0件 × drift 4 × 刺さる手9%」の三重が重なった例。

外れ値2件（大門20%・スターターの坊っちゃん51%）を均す案を提示したが、
**そのまま残す**と決定した。大門は「壁」として意図的に置く。

そのため以下は**既知かつ意図的**であり、後から「バランスの不具合」として扱わない。

- 大門の契約成功率が他より突出して低い（20%）
- 最初に選べる3人の難易度差が大きい（田中93% / 鬼塚73% / 坊っちゃん51%）
- 難易度カーブが解放順と対応していない（終盤の千鶴86%・早瀬86%より中盤の大門20%が難しい）

コード変更なし。

### 「誰とラウンドしても同じ」の原因と修正 — 正直が万能鍵だった

プレイして「選択肢に差がなくて、誰とラウンドしても大体同じ」という指摘。測って原因を特定した。

#### データは多様だった

まず疑ったところは全部問題なかった。

| 測ったこと | 結果 |
|---|---|
| 1ラウンドの構成 | 相手専用イベント 44% / 全員共通 36% / ミニゲーム 20% |
| イベントの「形」（3択のタグ組み合わせ） | 170イベント中 141通り |
| 同じイベントで正解が相手によって変わるか | **92%** が変わる |
| 他人の攻略法で挑んだときの損 | **18.1ポイント**（自分の好み92.2% vs 他人70.5%） |

「読む価値」は数字上あった。それでも同じに感じるのはなぜか。

#### 正体: `honesty` だけが万能鍵

**「とにかく正直を選ぶ」だけで 95.8% 勝てていた**（相手を読んだ場合96.3%、差 **0.5ポイント**）。
読む価値はあるのに、読まなくても勝てる。だから相手が誰でも同じ体験になる。

原因は3つ重なっていた。

1. **選択肢の生データ** — タグ別の生 trust 平均で `honesty` が **+6.49**、しかも creep **−0.31**（creepまで減る）。
   比較: `bold` +2.06 / `hype` +0.96 / `flattery` +0.43。
   正直の選択肢がある65イベントのうち **83%** でそれが最大 trust。
2. **キャラの反応** — `honesty` に正の反応を持つキャラが **15人**、負の人が **0人**。
3. **好みの重複** — `honesty` を好むキャラ 11人。誠実系6タグ（honesty/ethics/sportsmanship/serious/logic/etiquette）を
   複数同時に好むキャラが多く、「まともに振る舞う」だけで大半に効いた。

#### 効かなかった案（記録）

| 案 | 結果 |
|---|---|
| 生 trust を一律スケール（×0.6〜0.25） | 全戦略が一律に下がるだけ。差は 0.7〜3.5pt のまま |
| 契約の trust 閾値を 70 → 78 / 84 | **変化なし**（正直一本では trust が上限付近まで飽和するため） |
| 誠実系を1人1タグに排他化 | 正直一本 95.8% → 94.9%。ほぼ効かず |

閾値を上げても効かないのが決定的だった。**強すぎる一手がある限り、条件を厳しくしても同じ一手で通る。**

#### 効いた修正: 正直を嫌う相手を作る

`honesty` を嫌うキャラが **0人**だったのが本質。ノリ重視の4人に嫌わせた。
キャラ設定に無理がない（楽しければいい人に正直な指摘は無粋）。

| | |
|---|---|
| 正直を**嫌う**（trust −4 / fun −3・hatesTags 入り） | 坊っちゃん・光山・ナイス松本・星野 |
| 正直が**本当に刺さる**（trust +5〜+6） | 佐藤・桐生・黒田・鷹宮・早瀬 |
| その他 | trust **+1** に弱める（万能鍵から降ろす） |

大門は既に最難（20%）なので除外した。入れると1%まで落ちる。

あわせて誠実系の好みを1人1タグに排他化し、嫌いに「別の誠実さ」を入れた
（田中は礼儀を好むが攻めを嫌う、中村は理屈を好むが形式を嫌う、など）。

#### 結果

| | 変更前 | 変更後 |
|---|---|---|

### ミニゲームの単調さ — パットの強さをスワイプに変えた

「ミニゲームも単調」という指摘。数えると1ラウンド5回あるが、実質2種類しかなかった。

```
朝イチのスイング    バーを中央でタップ
最終パットの強さ    バーを中央でタップ   ← 同じ操作
最終パットの狙い    3択
昼の席選び          4択
昼のメニュー選び    6択
```

タップが2回で**完全に同じ操作**、残り3つは選択肢が形を変えただけだった。

#### 変更: 縦スワイプの長さで強さを決める

パットは「どれだけ強く打つか」を決める場面なので、引いて離す動作の方が素直。
朝イチのタップと操作が分かれる。

さらに**傾斜ごとに目標の強さを変えた**ので、状況を読む必要が出る。

| 傾斜 | 目標の引き量 | 文言 |
|---|---|---|
| 上り | 0.74 | 上りだ。しっかり引いて、離す |
| 平ら | 0.50 | 平ら。引きすぎるとオーバーする |
| 左右に曲がる | 0.58 | 曲がる。少し強めに引いて、離す |

同じ引き量でも傾斜によって結果が変わる。

```
引き0.50 → 上り:miss    平ら:perfect  曲がる:good
引き0.74 → 上り:perfect 平ら:miss     曲がる:miss
```

判定窓（perfect ±0.05 / good ±0.10）は従来と同じ数値で、集中力が低いほど狭くなる仕組みも維持。
目標帯はゲージ上に表示するので、判定と見た目は同じ数値から作っている。

#### 実装

- `PanResponder` で縦方向のドラッグ量を 0〜1 に正規化（引き幅 170px）
- パット用に回していたバーのアニメーション（`swingBarAnim` のループ）を撤去
- 指を離した時点で判定 → 従来と同じ `calcPuttResult` へ

#### 実機で直したこと

最初の実装では「下から上へ引く」がプログレスドットに隠れて画面下端で切れていた。
ヒントをゲージの上に移し、目標帯を指していない「ここ」ラベルを削除した。

|---|---|
| 判定の単体確認 | 傾斜4種 × 引き量5段階で意図通り |

### 答え合わせを作る — 結果画面に「今日の分かれ目」と失敗理由

### 後半に山場を作る — 締めの常設化と、進行による信頼の重み

「75%のラウンドが前半5ビートで決着し、後半5ホールが消化試合」への対応。

#### 締めのビートを常設にした

`closing` は3種のボーナスビートからの抽選だったため、**2/3のラウンドは締めが無いまま**終わっていた。
`BONUS_BEATS` から外し、毎ラウンド必ず発生させる。
`bonusBeatDone` は pre / lunchTalk と共用なので、締め専用に `closingDone` を分けた。

実測: 締めが出るラウンド **33% → 95.4%**（残り4.7%は stage 9 プールが尽きた場合）。

#### 締めの重みを上げるだけでは効かなかった（記録）

stage 9 の trust を ×1.5 / ×1.8 / ×2.2 と上げても、前半で決まる割合は 73.9% → 72.6% でほぼ動かない。
**1ビートでは5ビート分の蓄積を覆せない**。

#### 効いたのは「進行による信頼の重み」

根本は「技能0.6でも前半5ビート終了時に契約ライン（信頼70）へ到達してしまう」こと。
そこで信頼の動く量に進行の重みを掛けた（`trustPhaseWeight`）。

| 区間 | 重み | 理屈 |
|---|---|---|
| 前半（ホール1〜4） | **×0.45** | 序盤は様子見。まだ相手の心は動かない |
| 昼（ホール5） | ×1（既存の1.5倍はそのまま） | — |
| 後半（ホール6〜9） | **×1.4** | 打ち解けてきて反応が大きくなる |
| 締め | **×2.0** | 本題が出る場。ここで決まる |

あわせて stage 9 イベントの trust を **1.8倍**（52選択肢）。平均 3.17 → 5.63。

#### 結果

| | 改修前 | 改修後 |
|---|---|---|
| 締めが出るラウンド | 33% | **95.4%** |
| 後半で結果が動くラウンド | 24.8% | **42.0%** |
| 中間（5ビート）時点の信頼平均 | 70（＝契約ライン） | 58 |
| 契約成功率 | 97.7 / 82.1 / 61.1 / 42.1 / 12.5 | **96.7 / 80.0 / 60.6 / 42.0 / 11.8** |

ビートごとの振れ幅は右下がり（昼10.1 → 最終盤2.8）から、
**昼〜後半にピークが移り、最終ビートが盛り返す形**になった。

```
改修前  6.9 7.0 5.6 5.9 10.1 7.1 4.6 4.8 3.5 2.8   ← 右下がり
改修後  4.7 5.2 4.2 3.9  8.6 9.9 6.8 6.4 4.8 6.2   ← 序盤は静か、昼〜後半が山、締めで盛り返す
```

難易度は改修前とほぼ同じに保った（数値の上下は1ポイント以内）。

**回帰**: 共通プール到達 167/167、ハング 0/4200、相談ラウンド 200/200、`tsc --noEmit` 通過。

### 「一緒に回って分かったこと」を蓄積する

読む材料が `hint` の1行しか無かったので、**回った回数だけ増える材料**を足した。

#### 仕組み

- `HoleResult` に `tags` を追加（`rank` / `trustDelta` / `choiceText` と同じ流れ）
- 結果画面の副作用で、`rank === 'good'` の手のタグを `liked`、`worst` の手のタグを `hated` に溜める
- 契約の成否に関わらず記録する。回った経験は残る
- store に `discovered: Record<CharacterId, { liked: Tag[]; hated: Tag[] }>` を追加・永続化（重複は除く）
- `tagInsights.ts`（新規・39タグ）でタグを日本語の一文に変換。タグ名は表に出さない

| 0（銀座） | 1% |

完全に連動している。自然減は「信頼を稼ぎ続けさせる」ための難易度なのに、

## スコア条件をミニゲームに結びつける

### 直前の状態

契約の3条件のうち、実際に落としていたのは信頼だけだった（技能0.6）。

| 条件 | 落とす側に回った割合 |
|---|---|
| 信頼 84 以上 | 39.7% |
| 距離 85 以下 | 0.0% |
| 相手のスコアが伸びた | 0.1% |

信頼と距離を満たした887ラウンドのうち、スコアで落ちたのは4件。
improvement の中央値 +16、最小 -2。条件として機能していなかった。

### 何を変えたか

**基準を「無難な選択をし続けたら」から「相手の平均スコア」に変えた**

反実仮想の基準は、
- 何と比べられているのかプレイヤーから見えない
- 自然減を入れないと自然減の大きい相手ほど不利、入れると基準が弱くなりすぎて条件が死ぬ

という二択に陥っていた。`character.avgScore18` を基準にすれば、
比較対象がプロフィールに出ている数字そのものになる。
`simulateNeutralGauge` と `findNeutralChoiceIndex` は削除。
これに伴い未使用になった `findEventById` も削除した。

**スコアを動かす主役をミニゲームにした**

```
相手のスコア = 平均 + ゲージの影響（従） + ミニゲームの影響（主） + 昼の影響
```

ゲージから作った値はどう捻っても信頼の読み替えにしかならず、
条件を増やしても「信頼が足りたか」を二度聞いているだけになる。
ゲージを経由しない入力は自分のショットと最終パットだけなので、そこを主役にした。

朝イチの受け答え（`morningMomentum`）は**入れていない**。
あれは選んだ選択肢の信頼と creep から作られる値なので、
混ぜるとスコア条件がまた信頼の写しに戻る（実測でスコアで落ちる率が 1.9% までしぼんだ）。

### 重みの決定

選択の腕0.8固定・信頼と距離を満たしたラウンドのうちスコアで落ちる割合。

| 自分のショット / 最終パット | 下手 | 普通 | 上手 |
|---|---|---|---|
| momentum込み 3/1/2・4/1/3 | 1.9% | 0.7% | 0.5% |
| **4/1/3・6/1/5** | **22.2%** | **7.0%** | **1.6%** |
| 5/1/4・7/1/6 | 35.2% | 12.0% | 1.1% |
| 5/2/5・8/2/7 | 38.6% | 16.4% | 4.2% |

5/1/4 以上はパットを外す人の契約率が 25pt 落ちて罰が重すぎる。

### 結果

```

ミニゲームができる人は据え置き、外す人だけ難しくなった。
腕が契約率 14pt 分の価値になり、信頼とは別の軸が立った。

### 表示

改善打数に -12〜+10 の頭打ちを入れた。素のままだと -15〜+18 まで開き、
平均88の相手が 60 で回ったことになる（ほぼプロ）。

文面も基準に合わせた:
`ベースライン: 80` → `いつもの 82`、
`あなたの接待で N打 改善しました` → `いつもより N打 よく回りました`。

## 距離（creep）を生きた軸にする — 誘惑の追加

### なぜしきい値を動かすだけでは駄目だったか

契約の距離条件は 0.0〜0.1% しか働いていなかった。
理由を測ったところ、**creep を完全に無視して打っても creep が溜まらない**。

| プレイヤー | creep 中央値 | 上位10% | 成功率 |
|---|---|---|---|
| creep を避ける | 19 | 45 | 75% |
| creep を完全に無視 | 23 | 54 | **76%** |

無頓着なほうが成功率が高い。距離感を気にする意味がなかった。

原因は選択肢の側にあった。750件のうち
**「信頼+4以上かつ creep+4以上」＝踏み込めば伸びるが引かれる誘惑は12件（1.6%）**しかない。
`creep+3以上` は177件あるが、それらは信頼も低い＝見るからに悪手なので誰も選ばない。

この状態でしきい値だけ下げると、慎重に打った人と無視した人の creep がほぼ同じ（19 vs 23）なので
**判断ではなく運で落ちる**。スコア条件で潰したばかりの「見えない失敗」を作り直すことになる。

### やったこと

`over_support` / `flattery` / `over_praise` / `analysis_praise` を持ち、
かつ creep+3 以上、かつ不正タグを含まない選択肢 **82件（11.2%）** のデルタを書き換えた。
**発言そのものは変更していない。**

- 信頼 = 同じイベント内の他の選択肢の最大値 + 3（上限9）
- creep = 6以上（extreme は7以上）

最初は「信頼 = max(既存, 5)」としたが、他の選択肢との差が中央値 +1 にしかならず、
39% は同等以下だった。+1 の見返りで creep+6 を払う人はいない。
差を +3 にして初めて選ばれるようになった（現在は差の中央値 +3、損なのは 15%）。

### しきい値の再設定

| | 変更前 | 変更後 | 根拠 |
|---|---|---|---|
| 契約の距離上限 | 85 | **50** | 85 は誰にも当たらない。50 で 2.9%（慎重）/ 8.1%（無頓着） |
| 段階罰 | 70 / 90 | **40 / 55** | 70 まで上がる経路が実質なかった |
| ビネット | 70 / 90 | **35 / 50** | 罰より一段手前。翳ってから罰が来る順にする |
| 破局 | 100 | 100（据え置き） | creep は100で頭打ちなので上げられない。稀な破局として残す |

### 結果

3条件すべてが働くようになった（技能0.8・ミニゲーム0.6）:

| プレイヤー | 成功 | 信頼で落ちる | 距離で落ちる | スコアで落ちる |
|---|---|---|---|---|
| 距離を測る | 71.0% | 21.4% | 1.3% | 6.1% |
| 信頼だけ追う | 71.4% | 20.3% | **4.2%** | 4.0% |

距離で落ちる率が 0.0〜0.1% → 1.3〜4.2% になり、打ち方で3倍の差がつく。

契約成功率（技能 1.0/0.8/0.6/0.4/0、ミニゲーム0.6）:

```
誘惑を足す前   91.0 / 77.6 / 58.9 / 41.8 / 11.7
誘惑を足した後 87.1 / 73.3 / 54.5 / 36.5 / 10.8
```

全体に 4pt ほど難しくなった。

### 確かめられなかったこと（正直に）

**「溜まったら断る」適応的な打ち方が、無視する打ち方に明確に勝つとは言えなかった。**

| 設定 | 適応 − 無視 |
|---|---|
| 上限50 段40/55 罰1/2,2（採用） | +0.7pt |
| 上限45 段35/45 罰2/4,3 | +2.4pt |
| 上限40 段30/40 罰2/5,4 | +3.5pt |
| 上限45 段30/45 罰3/6,4 | +0.4pt |

罰を強めれば差は出るが、同じ設定でも符号が振れる（信頼80で -0.2pt、信頼78で +2.8pt）ため
ノイズと区別できない。かつ罰を強めると慎重な人まで巻き添えになり、
技能0.8の成功率が 73 → 67 まで落ちる。

つまり現状の誘惑は**EVが釣り合っている**。取っても取らなくても大差ない。
「consequence（結果に出る）」にはなったが「decision（正解のある判断）」には至っていない。
ここを詰めるにはおそらく creep をプレイヤーに見せる必要があり、
ゲージを一切表示しないという既存の設計方針と衝突する。判断は保留。

### 実機確認

坊っちゃん（Avg 98）で1ラウンド。作戦「笑わせる」（当たり）、接待グレード S、
しかし最終パットを外して 102。

```
18H: 102
いつもの 98
いつもより 4打 崩れました
...
届かなかった
スコアを伸ばしてあげられなかった
```

場は盛り上がったのに相手のスコアが伸びず落ちる、という新しい負け方が実際に出た。

ビネットの閾値変更は実機では未確認（creep 35 まで上げる操作をこの環境から再現できなかった）。

**回帰**: 選択肢734件で異常0・ID重複0、共通プール到達 167/170、ハング 0/4200、
相談ラウンド 200/200、ゲージの範囲外 0件、締め無しは全件 `creep_explosion`、
反応ランク good38/neutral28/bad16/worst18%、`tsc --noEmit` 通過。

## 音をつける — 素材を使わず波形から作る

### 方針

ライセンスを持っていないため、**音源ファイルを一切使わない**。
Web Audio API のオシレータとノイズだけで、その場で合成する。
素材が存在しないので権利者もライセンス表記も発生しない。
`expo-av` も入れていないので依存もバンドルも増えない。

ネイティブ（iOS/Android）には Web Audio が無いので、そこでは黙って何もしない。
現状の配信先はブラウザ（Vercel）なので実害はない。
BGM は作っていない。合成でループ音楽を作ると、無音より悪くなる。

### 音の種類（全6種）

| 名前 | 場面 | 作り |
|---|---|---|
| shot | 自分のショット | ノイズの一撃（2.6kHz帯）＋低い胴鳴り |
| cupIn | カップイン | 下降する3音、間を詰めて |
| cupMiss | 外した | 高い音が下がって、ノイズで鳴りきらない |
| good | 相手に刺さった | 上がる2音（D5→G5） |
| bad | 相手を怒らせた | 半音でぶつける低音（C4＋B3） |
| tap | 設定の切り替え | ごく短いクリック |

中間（neutral / bad ランク）では鳴らさない。
毎回鳴ると「今の一手が効いたか」の合図として機能しなくなる。

### 検証

オフラインレンダリングで全6種の波形を測定。

| 音 | ピーク | RMS | 長さ | 音割れ |
|---|---|---|---|---|
| shot | 0.099 | 0.0040 | 0.07秒 | なし |
| cupIn | 0.088 | 0.0085 | 0.32秒 | なし |
| cupMiss | 0.061 | 0.0043 | 0.12秒 | なし |
| good | 0.056 | 0.0059 | 0.20秒 | なし |
| bad | 0.051 | 0.0045 | 0.16秒 | なし |
| tap | 0.021 | 0.0010 | 0.02秒 | なし |

無音のものは無く、割れているものも無い。
ただしピークが -20dB 程度で環境音のある場所では聞こえないため、
全体音量を 0.18 → 0.32 に上げた（重なった場合の理論上限でも 0.40 で割れない）。

### 設定

`settings.sfxEnabled` は保存フィールドだけあって**読む経路も書く経路も無かった**。
ストアに setter を足し、起動時の復元でも鳴らす側に伝えるようにした
（ここを忘れると「オフにして閉じたのに次に開くと鳴る」）。
設定画面が無いのでタイトル画面に「音 ON / 音 OFF」を置いた。

実機で確認: ボタンが表示され、押すと `sfxEnabled: false` が保存されて
オシレータが生成されなくなり、もう一度押すと `true` に戻って実際に生成される。

### 残っていること

`settings.bgmEnabled` は依然として使われていない。
BGM を作らない判断なので、フィールドを消すか、将来のために残すかは保留。
