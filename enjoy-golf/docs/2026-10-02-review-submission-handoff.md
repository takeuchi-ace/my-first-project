## 次にやる順番

### 1. 実機で一周する（**build 2 で行う**）

**build 1 には新しいミニゲームが入っていないので、一周は build 2 で行う。**
（順番としては「3. build 2 を焼く」を先に済ませ、TestFlight で build 2 を入れて一周する。提出はその後）

TestFlight から入れて、ひと通り遊ぶ。**ここを飛ばして提出しない。**
Web では出ない不具合が疑われている。ミニゲームの作り直しは **Web（375×667）でしか確かめていない。**

| 優先 | 見るところ |
|---|---|
| **最優先** | **パットの引き（グリーン上で後ろへ引く）**。引いている間に画面がスクロールしないか。iOS のタッチで後ろへ引いて離すと打てるか。ここが死ぬとゲームが成立せず、審査で落ちる |
| 高 | パットの説明文とグリーンが、SE 級の小さい端末・ノッチ端末でスクロールなしに収まっているか |
| 高 | 朝イチの3タップ。タップの反応が遅れて印を外しやすくないか（Web より実機のほうがタッチの遅延が大きい）。タップがすぐ効くか |
| 高 | 朝イチの画面が **1番ホール**（地図・パー・進行の点）を出しているか |
| 高 | ラウンド中の**端からの右スワイプ**で戻れてしまわないか。戻れると初回契約のカットインを取りこぼす |
| 中 | ノッチに木目ヘッダー・紹介画面の頭が潜っていないか |
| 中 | ドット絵がぼやけていないか |

### 2. 音の扱い — **決定済み：A（ネイティブではトグルを出さない）**

iPhone では**音が一切鳴らない**。効果音を Web Audio API で合成していて、
ネイティブに Web Audio が無いため（`src/lib/sound.ts` の冒頭に理由が書いてある）。

タイトルの「音 ON」は画像に描き込まれているので、トグルを隠すだけでは文字が残る。
そこで:

- ネイティブは `assets/title_screen_native.png`（「音 ON」を芝生で塗り消した同寸画像）を使う
- ネイティブではトグルの `Pressable` を置かない
- Web は従来どおり（画像・トグルとも変更なし。ブラウザで確認済み）

**build 2 で反映。**実機ではタイトルに「音 ON」が出ていないことを確認する。
ネイティブで鳴らすなら 1.1 以降で B（同じ波形を WAV に書き出して `expo-audio`）。

### 3. build 2 を焼く

```bash
cd ~/おもちゃ箱/enjoy-golf
npx eas-cli@latest build --platform ios --profile production
```

対話で Apple へのログインを聞かれる（`s.takeuchi@hinano.co.jp` + 2ファクタ）。
証明書・プロファイルは既にあるので、作り直しは聞かれないはず。

**焼けたら `.ipa` のパスを Claude に渡すこと。** 毎回やる照合:

- `CFBundleVersion` が 2 か
- `UIDeviceFamily` が `1` だけになったか（iPad が外れたか）
- `ITSAppUsesNonExemptEncryption: false` が入っているか
- 今回の修正がバンドルに載っているか（音：`title_screen_native.png` がアセットに入っているか）
- パット・朝イチの作り直しがバンドルに載っているか（`TeeShotMeter` の文言「どこまで飛ばす？」を utf-8 / utf-16-le で照合）

**JS は Hermes バイトコードなので `strings` では日本語を拾えない。**
utf-8 と utf-16-le の両方でバイト列照合する。1.0 で「修正の入っていないビルドを
審査に出していた」事故が起きた箇所。

### 4. スクリーンショット 6枚

**iPhone 6.9インチ（1320×2868 または 1290×2796）縦向き。iPad は不要。**

## 審査について

### 初回は時間が読めない

麺の細道（2026年8月）の実測：**8/7 提出 → 8日間沈黙 → 8/11 問い合わせ →
8/14 Guideline 2.1（情報要求）→ 返信 → 承認**。2週間以上かかった。

**11月リリースなら、10月のうちに初回を通しておく。**2回目以降は速い。

### Guideline 2.1 は却下ではない

新規アプリの定番で、「情報が足りない」という差し戻し。**返信すれば審査が再開する。**
件名（There's an issue with your submission）だけで判断しない。
**メールは Apple Account のアドレスに届く。迷惑メールも見る。**
対処は `appstore-release` スキルの `reference/情報要求への回答.md`。

### このアプリ固有の論点

- **年齢レーティングは 4+ にならない。**会話に酒類の言及が47箇所ある
  （乾杯15・酒13・ビール8・日本酒4・ウイスキー4・ハイボール2・ワイン1）。
  低く申告して差し戻されるほうが高くつく。根拠は `appstore-answers.md` §1
- **「接待」「契約」「紹介」が並ぶので、ビジネス実務アプリと誤読されうる。**
  審査メモに架空・娯楽である旨を先に書いてある（`appstore-answers.md` §4）
- **幻想画の肖像**は実在の人物ではない。審査メモとプライバシーポリシー第9項の両方に明記済み
- **通信ゼロ・権限ゼロ・課金なし。**App Privacy は「データを収集していません」

### 審査中は触らない

**掲載文・スクショ・ビルドを触ると審査をやり直させる可能性がある。**
提出したら結果が出るまで待つ。コードは進めてよいが、ビルドは上げない。
年齢レーティングだけは審査対象のメタデータではないので、審査中でも変更できる。

## 触ってはいけないもの

- **契約判定まわりの実測値** — 大門の20%、坊っちゃんの低い初期難易度、ACEの引用率は決着済み。蒸し返さない
- **プレイヤーの発言そのもの** — 極端な・ふざけた台詞はそのまま。変えてよいのは delta・tag・条件だけ
- **難易度を下げる変更** — 一貫して「下げない」。やるなら上げる方向
- **パットの吸い込みの強さ**（`puttPhysics.ts` の `FUNNEL_*`・`CAPTURE_SPEED`）— ぎりぎりで止めてある。強めると左右の傾斜でまっすぐ打って入る（読む意味が消える）、弱めると ふつう が下限を割る。触ったら `node tools/minigame-sim.js` を回す
- **第三者の音源** — ライセンスを持っていない。効果音は自作波形のみ

`dabisuta` `dream-breeder` `sim-city` `昆虫HP` が同居している。
