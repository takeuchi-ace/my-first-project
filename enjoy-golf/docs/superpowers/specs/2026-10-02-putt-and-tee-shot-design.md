# 設計：最終パットと朝イチショットの作り直し

2026-10-02

build 2（審査提出用）を焼く前に、ゲームの芯にある2つのミニゲームを作り直す。
決定経緯：日程は「両方やってから build 2」（2〜3日の後ろ倒しを許容）。

---

## なぜ作り直すか

### パット

1. 狙い（会話の3択）と強さ（横ゲージ）が分かれていて、グリーンの絵は見るだけ
2. 横へ引く操作。パターは後ろへ引くもので、手の感覚と合わない
3. 傾斜バッジが答えを言っている（「◀ 左に傾斜」→ 右狙い）。読む余地がない
4. 結果は「狙いが正解か × 強さ」の表引き（`calcPuttResult`）。ボールは決め打ちの曲線を描くだけで、外れ方が操作と無関係
5. グリーンが 200×140 と小さく、ScrollView の中にある（実機でドラッグが取られる懸念の原因）

### 朝イチ

1. 「動くバーを中央で止める」を3回。速くなるだけ
2. 弾道は3通りの決め打ち着地点へ直線移動
3. 「どこまで飛ばすか」を選べない。接待ゴルフなのに相手との飛ばし合いがない

## 1. パット：グリーン上で引いて打つ

### 流れ

傾斜の説明と相手の助言 → **会話の3択（変更なし）** → グリーン画面 → 転がる → 結果

- 会話の3択（`buildPuttingGameEvent`）は**社交の選択として残す**。delta・タグ・返事（`getPuttAimReply`）は変えない
- 3択で選んだ線は、グリーン上に**淡いガイドとして表示するだけ**。実際にどこへ打つかは自由
  （「右ですね」と言っておいて自分の読みで打つ、ができる）

### 操作

- グリーンを画面幅いっぱいに描く。パット画面の間は **ScrollView のスクロールを止める**（`scrollEnabled={false}`）
- ボールに触れて**後ろへ引き、離して打つ**。引いた向きの反対へ打ち出し、引いた長さが強さ
- 引いている間は**打ち出し方向の短い線だけ**を出す。曲がりは見せない
- 引いた量が最小値（今の `PUTT_PULL_MIN` 相当）未満なら打たずに戻す
- 引き量には上限がある（上限で頭打ち。それ以上引いても強くならない）
- 集中力が低いほど、引いている間の方向線が揺れ、離した瞬間の向き・強さに小さなブレが乗る
  （今の `focusWindowScale` と同じ式で、ブレの幅を決める）

### 転がり — `src/logic/puttPhysics.ts`（新規）

- `simulatePutt({ slope, angle, power, noise })` → `{ path: [x,y][], result: PuttResult }` の**純粋関数**
- 画面（`PuttGreenView`）は `path` を再生するだけ。判定は画面に持たない
- モデル：
  - 傾斜は一定の加速度（`left` / `right` は横向き、`uphill` は奥から手前向き、`flat` は 0）
  - 芝の抵抗は一定の減速。速度 0 で停止
  - 固定刻み（1/120秒相当）で積分。乱数は使わない（ブレは呼び出し側が `noise` として渡す）
- 判定：
  - カップの上を**捕捉速度以下**で通過 → `in`（そこで止まり、沈む）
  - カップの縁にかかる距離を通過、またはカップ上を捕捉速度より速く通過 → `lip_out`
  - それ以外（ショート・オーバー・ライン外れ）→ `miss`
- 結果は今と同じ3種類。相手の反応表（`ownPlay.ts` の `PUTT`）と打数への効き（`minigameScoreEffect`）は変えない

### 表示

- 傾斜バッジと説明文は残す。向きが分かっても**どれだけ曲がるか**は読む必要がある
- 傾斜の矢印は控えめにする（向きだけ。量は示さない）
- 結果ラベル（カップイン！／LIP-OUT…／MISS…）と相手の反応文は今のまま

### 消すもの

- `calcPuttResult`（表引き）、横ゲージ（`puttPullGauge*`）、`PUTT_POWER_TARGET` と `powerZoneStyle`
- `PuttGreenView` の `computePuttPath`（決め打ち曲線）とエイム3本線

## 2. 朝イチ：3タップ＋飛ばし合い

### 流れ

`own_shot_intro` → **`own_shot_talk`（構えたところで話しかけられる）** → `own_shot_swing`（3タップ） → `own_shot_result`

- 話しかけは今「1段目のタップ後」に出ている。3タップは一続きの動きなので途中で止めず、**1回目のタップの前**に移す
- 効き方は今と同じ：
  - 応じる：信頼 +4、この一打は PERFECT が出ない
  - 流す：信頼 −2、ショットに影響なし

### 操作（みんゴル式）

1. タップでスイング開始。バーが 0 から伸びる
2. 2回目のタップで**パワー**確定（0〜1）。押さずに端まで行ったら 1 で確定し、折り返す
3. 戻ってくるバーを3回目のタップで中央に止める＝**インパクト**

- パワーのバー上に**相手のティーショットの到達点**を印で出す（後述）
- インパクトの窓は `focusWindowScale(focus)` × **パワーが高いほど狭くなる係数**
- **パワーが「刻み」域（下限未満）だと PERFECT は出ない**（応じたときと同じ扱い）
- バーが端（0）を過ぎても押さなければ MISS

### 結果

- PERFECT / GOOD / MISS はインパクトのずれで決まる（窓の内側/外側）。打数への効き・`ownShotReaction` は変えない
- 飛距離 = パワー × 出来の係数（PERFECT 1.0 / GOOD 0.9 / MISS 0.6）
- インパクトのずれの符号でフック／スライス。俯瞰図（`MorningShotView`）の弾道を曲げ、着地点を横にずらす

### 飛ばし合い — 相手を越えたか

相手の到達点は、直前の相手のショット（`state.morningShot`）から決める：

| 相手の結果 | 到達点（パワー換算） |
|---|---|
| `great` | 0.80 |
| `normal` | 0.62 |
| `ob` | 印を出さない。飛ばし合いの増減なし |

自分の飛距離が相手を越えたかで信頼を上乗せする（`applyMinigameResult` 経由。仮置き、回帰で詰める）：

| 相手の型 | 越えた | 越えなかった |
|---|---|---|
| `respects`（腕を認める） | +2 | −1 |
| `indifferent`（気にしない） | 0 | 0 |
| `prefersLead`（上に立ちたい） | −3 | +2 |

表は `src/logic/ownPlay.ts` に `outdriveReaction(stance, outdrove)` として足す。

### 消すもの

- `SWING_STEPS` の3段構成、`swingScoresToResult`、段ごとのチップ表示

## 3. 難易度と回帰

### 難易度は下げない

`tools/minigame-sim.js`（新規・リポジトリに残す）で、腕前の違う打ち手を模して新旧を比べる。

- 朝イチ：タップのずれを σ=0.15 / 0.08 / 0.04 の正規分布で模す。旧方式（3段）と新方式（3タップ）の PERFECT / GOOD / MISS 率を並べる
- パット：引く向き・長さのずれを3段階の σ で模し、「正しい読み」で打った場合の in / lip_out / miss 率を旧方式（正解の狙い＋強さの窓）と並べる
- **新方式の PERFECT 率・in 率が、どの腕でも旧方式と同じか低いところ**で係数を止める

### 契約率

- `tools/regression.js` に飛ばし合いの増減を足す（ミニゲームの腕 `mg` で、越えたか否かを確率的に決める）
- 変更前に一度回して基準値を取り、変更後と比べる。決着済みの実測値（大門の20%など）が崩れないこと

### そのほか

- `npx tsc --noEmit`
- Web で両ミニゲームを通しで遊ぶ。iPhone 幅（375）でドラッグがスクロールに取られないこと
